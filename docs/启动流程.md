# 启动流程 (Startup Guide)

> 本文档面向**开发 / 部署 / 试用**三类人员,详细说明如何从零把项目跑起来。
> 涵盖: **后端启动、前端启动、Demo 模式(无任何外部依赖)、生产部署** 四种场景。

---

## 0. 环境要求

| 工具 | 版本 | 用途 |
|---|---|---|
| **JDK** | 21+ | 后端编译/运行 |
| **Maven** | 3.8+ | 后端依赖管理 |
| **Node.js** | 18+ | 前端构建 |
| **pnpm / npm / yarn** | 任一 | 前端包管理 |
| **Docker** *(可选)* | 24+ | 生产依赖: PG + Redis |

> **最低启动(仅 H2 + Mock)**: 只需要 **JDK 21 + Maven 3.8**,无任何外部依赖。

---

## 1. 三种启动模式

| 模式 | Profile | 数据源 | Redis | 大模型 | 适用场景 |
|---|---|---|---|---|---|
| **🅰 Demo 模式** | `dev` | H2 内存库 | 关闭 | Mock | **30 秒跑通**,无任何依赖 |
| **🅱 本地开发** | `local` | PostgreSQL | Redis | 真实 LLM | 真实联调 |
| **🅲 生产部署** | `prod` | PostgreSQL | Redis | 真实 LLM | 私有化部署 |

> 默认 Profile 为 `dev`,**直接 `java -jar` 即可启动**。下文优先讲 Demo 模式。

---

## 2. 🅰 Demo 模式 (推荐先跑通)

> **特点**: 无需任何外部依赖,启动后自带演示数据,可立即体验所有功能。

### 2.5 Demo 模式自带数据

| 数据 | 内容 |
|---|---|
| 用户 | `admin` (管理员) |
| 数据源 | `Demo MySQL` (id=1,元数据预填) |
| 表 | `demo.users` (5 字段) + `demo.orders` (5 字段) |
| 业务元数据 | `users.status`: 状态字段语义 + 筛选条件 |

## 3. 🅱 本地开发模式 (真实依赖)

> 适合联调 / 自定义 LLM / 自定义业务库。

### 3.1 启动 PostgreSQL + Redis

```bash
# 方式 A: Docker (推荐)
cd backend
docker compose up -d
# → postgres on 5432, redis on 6379

# 方式 B: 本机服务
# brew services start postgresql
# brew services start redis
```

### 3.2 初始化数据库

```bash
# 创建数据库
createdb -U postgres nl2sql
# 默认账号/密码见 application.yml: nl2sql / nl2sql_pwd
```

### 3.3 启动后端 (local profile)

```bash
cd backend
mvn -DskipTests package

# 启动并切换 profile
SPRING_PROFILES_ACTIVE=local \
  java -jar target/nl2sql-backend-1.3.0.jar
```

或使用环境变量:
```bash
SPRING_PROFILES_ACTIVE=local
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/nl2sql
SPRING_DATASOURCE_USERNAME=postgres
SPRING_DATASOURCE_PASSWORD=postgres
SPRING_DATA_REDIS_HOST=localhost
SPRING_DATA_REDIS_PORT=6379
LLM_BASE_URL=http://localhost:11434     # Ollama
LLM_API_KEY=demo
LLM_MODEL=qwen2.5-coder:7b
AI_AUTO_MOCK=false                       # 关闭 Mock,使用真实 LLM
```

### 3.4 启动本地 LLM (可选)

**Ollama** (推荐,本地免费):
```bash
# 安装: https://ollama.com/download
ollama pull qwen2.5-coder:7b
ollama serve
# → http://localhost:11434
```

**其他兼容 OpenAI 的服务** (vLLM / 通义千问 / DeepSeek / OpenAI):
```bash
# 在「大模型配置」页新增,设置:
#   baseUrl:  https://api.openai.com (或自建地址)
#   apiKey:   sk-xxxxx
#   model:    gpt-4o
```

## 4. 🅲 生产部署

### 4.1 服务端打包

```bash
cd backend
mvn -DskipTests clean package

# 输出
ls -lh target/nl2sql-backend-1.3.0.jar
```

### 4.2 配置生产环境变量

```bash
# /etc/nl2sql.env
export SPRING_PROFILES_ACTIVE=prod
export SPRING_DATASOURCE_URL=jdbc:postgresql://10.0.0.1:5432/nl2sql
export SPRING_DATASOURCE_USERNAME=nl2sql_prod
export SPRING_DATASOURCE_PASSWORD=***
export SPRING_DATA_REDIS_HOST=10.0.0.2
export SPRING_DATA_REDIS_PORT=6379
export SPRING_DATA_REDIS_PASSWORD=***
export LLM_BASE_URL=https://your-llm-gateway
export LLM_API_KEY=***
export LLM_MODEL=qwen2.5-coder-32b
export NL2SQL_JWT_SECRET=$(openssl rand -base64 32)   # 必须替换!
export NL2SQL_AES_KEY=***                            # 必须替换!
```

> 🔒 **生产密钥必须替换**:
> - `nl2sql.jwt.secret` — JWT 签名密钥
> - `nl2sql.aes.key` — 数据源密码加密密钥
> - `spring.datasource.password` — DB 密码

### 4.3 后台启动

```bash
# 方式 A: nohup
source /etc/nl2sql.env
nohup java -jar nl2sql-backend-1.3.0.jar \
  > /var/log/nl2sql/app.log 2>&1 &

# 方式 B: systemd (推荐)
cat > /etc/systemd/system/nl2sql.service <<'EOF'
[Unit]
Description=NL2SQL Backend
After=network.target

[Service]
Type=simple
User=nl2sql
EnvironmentFile=/etc/nl2sql.env
ExecStart=/usr/bin/java -jar /opt/nl2sql/nl2sql-backend-1.3.0.jar
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now nl2sql
systemctl status nl2sql
```

### 4.4 前端构建

```bash
cd frontend
npm install
npm run build    # 产物: dist/

# 用 Nginx 托管
cat > /etc/nginx/conf.d/nl2sql.conf <<'EOF'
server {
  listen 80;
  server_name nl2sql.your-domain.com;
  root /opt/nl2sql/frontend/dist;

  location /api/ {
    proxy_pass http://127.0.0.1:8080/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 60s;
  }

  location / {
    try_files $uri /index.html;
  }
}
EOF
```

### 4.5 防火墙与 HTTPS

```bash
# 开放 80/443
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https

# HTTPS (Let's Encrypt)
certbot --nginx -d nl2sql.your-domain.com
```

## 5. 首次使用流程

### 5.1 登录

打开 <http://localhost:5173>,使用 `admin / admin123` 登录。

### 5.2 配置真实数据源

进入 **数据源** 页,点击「新增」:

| 字段 | 填写示例 (MySQL) |
|---|---|
| 名称 | `生产 MySQL` |
| 数据库类型 | `MYSQL` |
| 主机 | `10.0.0.1` |
| 端口 | `3306` |
| 数据库 | `business_db` |
| 用户名 | `readonly_user` |
| 密码 | `(需只读账号)` |
| 备注 | `生产环境` |

点击「测试连接」→ 「保存」。

### 5.3 同步元数据

进入 **元数据同步** 页(或调用 API):
- 选择数据源 → 点击「同步」→ 等待完成
- 后台将抓取所有表/字段/注释/主键

### 5.4 配置大模型 (可选,Demo 模式已 Mock)

进入 **大模型配置** 页 → 「新增」:
- 名称: `通义千问`
- Base URL: `https://dashscope.aliyuncs.com/compatible-mode`
- API Key: `sk-xxx`
- Model: `qwen-coder-plus`
- 设为默认 + 启用

### 5.5 配置 Skill 模板 (可选)

进入 **Skill 模板** 页,可编辑默认模板,模板支持 7 个变量:

```
{{db_type}}           - 数据库方言
{{table_list}}        - 涉及的表列表
{{table_meta}}        - 表结构 (字段/类型/注释)
{{field_biz_meta}}    - 字段业务描述
{{filter_condition}}  - 预配置筛选条件
{{join_condition}}    - 关联关系
{{user_nl_query}}     - 用户原始自然语言
```

### 5.6 进入查询工作台

进入 **查询画布** 页:
1. 选择数据源
2. 选择数据库
3. 添加 1~N 张表
4. (可选) 配置字段业务描述
5. 输入自然语言 → 点击「生成 SQL」
6. 编辑 SQL → 点击「检查」(安全引擎校验)
7. 点击「执行 SQL」→ 看到结果
8. 可导出 Excel / CSV

## 6. 常见问题 (FAQ)

### Q1: 启动后访问 http://localhost:8080/api 报 404?

✅ **正常**。正确入口是 **前端** (<http://localhost:5173>)。
后端 `context-path=/api`,所有业务 URL 需加 `/api` 前缀。

### Q2: 启动报 `Cannot load driver class: org.h2.Driver`?

pom.xml 必须包含 H2 (runtime scope):
```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```
重新 `mvn package` 即可。

### Q3: 启动报 `Connection refused: localhost/127.0.0.1:6379`?

Redis 未启动。两种解决:
- 启动 Redis: `redis-server` 或 `docker compose up -d redis`
- **直接用 Demo 模式** (`spring.profiles.active=dev`),已排除 Redis 自动配置

### Q4: 登录返回 401 / 密码错误?

确认数据库中 admin 用户的密码是 BCrypt 加密的 `admin123`。
dev profile 启动时会自动 seed,可直接用 `admin/admin123`。

### Q5: SQL 生成返回 "无可用模板"?

需要至少 1 个 `isDefault=true` 的 Skill 模板。重启应用,dev profile 会自动注入。

### Q6: 数据源测试连接失败?

- 确认数据库可达 (telnet 主机 端口)
- 确认账号有权限
- Demo 模式的数据源 `127.0.0.1:3306` 本机无 MySQL 会失败 → 新增一个真实可达的数据源

### Q7: 前端 npm install 慢?

```bash
# 切换镜像
npm config set registry https://registry.npmmirror.com
```

### Q8: 端口冲突?

修改 `application.yml`:
```yaml
server:
  port: 8081    # 后端
```

修改 `frontend/vite.config.ts`:
```ts
server: { port: 5174 }  // 前端
```
