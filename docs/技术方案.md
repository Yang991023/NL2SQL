## 1. 架构总览

### 1.1 部署形态

```
┌────────────────────────────────────────────────────────────────┐
│                       内网环境（无外网）                          │
│                                                                │
│  ┌──────────────┐    HTTPS    ┌──────────────────────────────┐ │
│  │   浏览器      │◀──────────▶│  Nginx (反向代理 + 静态资源)   │ │
│  │ Chrome/Edge  │             └──────────┬───────────────┘   │
│  └──────────────┘                        │                    │
│                                          ▼                    │
│                  ┌─────────────────────────────────────┐      │
│                  │      Spring Boot 后端 (单体)          │      │
│                  │  ┌──────────┐  ┌──────────────┐     │      │
│                  │  │ REST API │  │ WebSocket    │     │      │
│                  │  └──────────┘  └──────────────┘     │      │
│                  └──────┬───────────────┬─────────────┘      │
│                         │               │                     │
│         ┌───────────────┘               └──────────────┐      │
│         ▼                                             ▼      │
│  ┌─────────────────┐                       ┌─────────────────┐│
│  │ PostgreSQL      │                       │ 只读DB-Proxy    ││
│  │ (元数据/业务)    │                       │ (HikariCP连接池) ││
│  │ 元数据缓存        │                       └────────┬────────┘│
│  └─────────────────┘                                │         │
│  ┌─────────────────┐                                ▼         │
│  │ Redis            │◀──── 会话/限流缓存     ┌──────────────┐  │
│  └─────────────────┘                       │ 目标数据库       │  │
│                                          │ MySQL/PG/Oracle │  │
│  ┌─────────────────┐                      │ 只读账号接入     │  │
│  │ LLM 代理服务     │◀──── http call       └──────────────┘  │
│  │ (Ollama/OpenAI  │                                          │
│  │  兼容接口)        │                                          │
│  └─────────────────┘                                          │
└────────────────────────────────────────────────────────────────┘
```

**关键约束**:
- 后端 ↔ 目标数据库: 仅 SELECT，账号最小权限
- LLM 调用: 通过统一代理层（兼容 Ollama / OpenAI 格式），可私有化部署也可走内网 API
- 静态前端构建产物由 Nginx 提供，Nginx 代理 `/api` 到 Spring Boot

### 1.2 模块划分（后端）

```
backend
├── nl2sql-api          # REST 控制器层
├── nl2sql-core         # 业务逻辑（查询/导出/校验）
├── nl2sql-ai           # LLM 调用封装
├── nl2sql-parser       # SQL 安全解析器（封装 JSqlParser）
├── nl2sql-datasource   # 多数据源适配（MySQL/PG/Oracle）
├── nl2sql-export       # 导出引擎（EasyExcel）
├── nl2sql-security     # JWT + AES 加密
└── nl2sql-infra        # 通用基础（缓存/日志/异常）
```

采用 Maven 多模块，便于后续按需裁剪，也方便单体起步。

## 2. 技术选型

### 2.1 后端栈

| 层 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 语言 | Java | 17 LTS | 稳定、生态成熟、团队上手快 |
| 框架 | Spring Boot | 3.3.x | 自动装配、生态广、社区活跃 |
| 持久层 | Spring Data JPA + MyBatis-Plus | - | JPA 处理元数据/业务表，MP 处理复杂动态 SQL |
| 连接池 | HikariCP | 内置 | 性能最优，Spring Boot 默认 |
| 安全 | Spring Security + JJWT | - | 标准 JWT 实现 |
| 缓存 | Spring Data Redis | - | 会话、限流、元数据缓存 |
| SQL 解析 | **JSqlParser** | 4.9+ | Java 生态最成熟的 SQL 解析器，支持多种方言 |
| 数据库迁移 | Flyway | - | 版本化管理 schema |
| API 文档 | springdoc-openapi | 2.x | 自动生成 Swagger UI |
| 导出 | **EasyExcel** | 3.3+ | 阿里开源，流式写入，10w 行内存可控 |
| 大模型客户端 | Spring AI | 1.x | 统一 OpenAI/Ollama/通义千问等接口 |
| 测试 | JUnit 5 + Mockito + Testcontainers | - | 单元/集成测试 |
| 构建 | Maven | 3.9+ | 多模块管理成熟 |
| 容器化 | Docker + docker-compose | - | 一键起依赖 |

### 2.2 前端栈

| 层 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 框架 | React + TypeScript | 18 / 5.x | 类型安全、生态广 |
| 构建 | Vite | 5.x | 快，HMR 体验好 |
| UI 库 | Ant Design | 5.x | 企业级中后台标配，含 Table/Tree/Form |

## 4. 核心业务流程

### 4.1 SQL 生成与执行（全链路）

```
┌──────────────────────────────────────────────────────────────────┐
│                          全链路流程图                             │
└──────────────────────────────────────────────────────────────────┘

[1] 用户在画布添加表 + 配置字段
   │
   ▼
[2] 输入自然语言描述 → 点击【生成SQL】
   │
   ▼
[3] 前端 POST /api/ai/generate-sql
   │
   ▼
[4] 后端构建 Prompt 上下文：
   │ - table_list  (画布中的表名列表)
   │ - table_meta  (对应表的结构 + 字段业务描述)
   │ - filter_condition (字段筛选逻辑)
   │ - join_condition   (关联条件)
   │ - user_nl_query    (用户自然语言)
   │ - skill_template   (选中模版)
   ▼
[5] 调用 LLM（Spring AI，统一接口）
   ▼
[6] 拿到生成 SQL → 回写前端编辑框
   ▼
[7] 用户编辑/确认 → 点击【检查】或【执行SQL】
   ▼
[8] 后端 SQL 安全校验引擎（共用）:
   │ (a) JSqlParser 解析 AST
   │ (b) 黑名单拦截 DML/DDL
   │ (c) 方言匹配 (MySQL/PG/Oracle)
   │ (d) 元数据比对引用对象
   │ (e) 高危逻辑检测 (笛卡尔积/全表扫描)
   ▼
   ├─ REJECT → 返回错误，前端红字提示，不入库
   ├─ WARNING → 弹窗让用户确认
   └─ PASS    → 进入下一步
   ▼
[9] HikariCP 获取只读连接 → 执行 SELECT（带超时 15s）
   ▼
[10] 结果渲染至查询结果展示区（按需分页/截断）
   ▼
[11] 记录操作日志（用户/数据源/SQL hash/结果条数/耗时）

                   ┌─────────────────────────┐
                   │ 用户点击【导出数据】      │
                   └─────────┬───────────────┘
                             ▼
                   [12] 复用执行结果（不重新查）
                   ▼
                   [13] EasyExcel 流式写入 (≤10w 行, 30s 超时)
                   ▼
                   [14] 返回 .xlsx / .csv 下载
```

### 4.2 数据源新增（含自动识别）

```
用户填连接信息 → 测试连接（HikariCP 拿连接 + 简单 SELECT 1）
  ├─ 失败 → 返回具体错误
  └─ 成功 → 保存（密码 AES 加密）
       → 自动识别 db_type (SELECT VERSION() 解析)
       → 拉取表清单 (information_schema / ALL_TABLES)
       → 拉取每个表的字段结构 (批量查询 + 缓存)
       → 写入 t_table_meta，写日志
       → 刷新前端左侧树
```

### 4.3 SQL 安全校验引擎（核心）

**抽象**:
```
SQL Security Pipeline
├── Layer 1: 预处理 (去除注释/空行)
├── Layer 2: JSqlParser 语法解析 → Statement 对象
├── Layer 3: 顶层校验 (StatementType → 仅允许 SELECT)
├── Layer 4: 方言校验 (与当前数据源 db_type 匹配)
├── Layer 5: 对象存在性 (遍历 Table/Column 引用，匹配元数据)
├── Layer 6: 高危逻辑
│   ├── 笛卡尔积: 检测多表 JOIN 是否都有 ON 条件
│   ├── 全表扫描: 检测无 WHERE 或无 LIMIT
│   └── 自动修复: 追加 LIMIT 1000
└── Output: { status: PASS/WARNING/REJECT, issues: [], fixed_sql: '' }
```

**统一入口**: `SqlSecurityService.checkAndFix(sql, dataSourceId) -> CheckResult`

【检查】和【执行SQL】共用此方法（防止绕过）。

## 5. 安全设计

### 5.1 三层防线

| 层级 | 措施 | 说明 |
|---|---|---|
| 网络 | 内网隔离 | 全部在内网 |
| 应用层 | JWT + 拦截器 + 注解 | 登录态校验 |
| 业务层 | SQL 安全引擎 + AES 加密 + 操作日志 | 核心 |
| 数据层 | 目标库只读账号，schema 隔离 | 终极保障 |

### 5.2 密码加密

- 算法: AES-256-GCM
- 密钥: 配置文件注入（生产用 KMS 或 Vault）
- 工具类: `AESUtil.encrypt/decrypt`

### 5.3 SQL 校验"防绕过"特别处理

- 即使前端禁用【执行】按钮，后端 API 仍走完全套校验
- 即使 SQL 由用户手动写入（即非 AI 生成），仍走完全套校验
- JSqlParser 失败 → **直接 REJECT**，不进入执行环节
- 超时控制：连接超时 5s + 查询超时 15s，强制 SET STATEMENT_TIMEOUT (PG) / MAX_EXECUTION_TIME (MySQL)

## 6. 性能与限流

| 场景 | 指标 | 方案 |
|---|---|---|
| 单库元数据加载 | ≤ 2s | 启动时拉一次全量缓存 + 后续增量 |
| SQL 执行 | 单次 ≤ 15s | SET query_timeout |
| 导出 | 10w 行 ≤ 30s | EasyExcel 流式 + 异步任务池 |
| 并发查询 | < 50 | HikariCP max-size=20 + 简单信号量 |
| 元数据缓存 | Redis + 本地 Caffeine | 双层 |
| 大模型调用 | ≤ 5s | Spring AI 设置 readTimeout |

## 8. 关键技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 幻觉（生成错误 SQL） | SQL 质量差 | ① Prompt 严格约束 ② JSqlParser 兜底 ③ 对象存在性校验 |
| JSqlParser 不支持某些方言语法 | 误判 REJECT | 选择宽松模式 + 语法错误时给出详细 hint |
| 目标数据库慢查询 | 服务被拖垮 | 强制超时 + max rows + 连接池隔离 |
| 大表元数据拉取慢 | 连接超时 | 分页拉取 + 后台异步 + 缓存 |
| Oracle 方言差异大 | 解析失败 | 连接层使用方言特定的 metadata SQL |
